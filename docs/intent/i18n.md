# Intent: i18n (EN/ID)

Confirmed with user on 2026-08-31.

- **Outcome:** EN/ID i18n across `web` and `landing` UI, plus chat replies that mirror the user's message language.
- **User:** Indonesian-majority users; they should land on Bahasa by default and chat naturally in either language.
- **Why now:** the app is English-only while most users are Indonesian.
- **Success:** UI renders fully in both languages; device detection picks ID for anything non-EN; chat replies follow the message's language (numbers-only or language-ambiguous messages fall back to the active UI language).
- **Constraint:** `core` has no translation layer. The only `core` change is the chat system prompt reading a `locale` field (`'id' | 'en'`) sent per chat request by `web`. No schema changes; UI language preference persists in `localStorage`.
- **Out of scope:** translating AI-generated content server-side, per-account language persistence, RTL support, locale-aware date/number formatting beyond what the i18n library provides by default.

## Decisions

| Decision | Choice |
|---|---|
| Surfaces translated | `web` (React SPA) and `landing` (Astro) UI strings only |
| Chat reply language | Auto-mirror the user's most recent message via system prompt; fallback to active UI `locale` |
| Default language | Device detection; anything non-EN defaults to ID |
| Preference persistence | `localStorage` (no account column, no `core` schema change) |
| `web` i18n approach | Client-side switcher (library TBD at implementation, e.g. `react-i18next` or lightweight custom) |
| `landing` i18n approach | Astro i18n routing: `/id/` as default locale (root serves ID), `/en/` for English; device-detect redirect on first visit |
| Payload contract | `web` sends `locale` field on each chat request; `core` validates via DTO and injects into system prompt |
